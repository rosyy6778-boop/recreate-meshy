# Meshy 登录首页重构产品说明


## 一、方案摘要

这次重构重新定义登录后首页承担的任务：从“展示 Meshy 能生成什么”，转向“帮助用户开始、继续并推进一项 3D 工作”。

原 Meshy 登录首页已经具备清晰的生成入口和丰富的社区内容，但页面的核心体验仍偏向一次性生成：新用户需要自己判断从哪里开始，老用户回到首页后缺少连续工作的入口，社区作品能够证明生成效果，却较少解释这些能力如何进入真实的 3D 生产流程。

因此，本方案将首页重构为一个以任务为中心的 3D 创作工作台：

- 顶部保留 Meshy 熟悉的产品导航与账户体系，降低改版带来的认知成本。
- 首屏用“单个资产 / 创建项目”区分两种根本不同的工作目标。
- 同时提供直接生成与智能助理，让明确需求和模糊需求都能开始。
- 在生成前增加图片检查、模式比较与积分提示，减少无效消耗和结果落差。
- 在创建入口下方增加“继续工作”，让老用户从项目上下文继续，让新用户获得可执行的起点。
- 将社区内容下沉为灵感与复用层，不再与核心工作区争夺首屏注意力。

一句话概括：

> 把 Meshy 首页从“AI 3D 作品橱窗”升级为“从创意输入到下一步行动的 3D 工作台”。

## 二、原体验中的核心问题

### 1. 首页知道用户能生成，但不知道用户要完成什么

原体验以生成方式和社区作品为主要组织维度，更适合回答“Meshy 能做什么”。但用户真正进入工作区时，通常带着更具体的目标，例如制作一个独立角色、完成一组风格统一的道具，或者把已有模型推进到贴图、拆件、绑定等后续环节。

当产品只提供统一入口时，用户需要自己把目标翻译成工具和步骤，复杂度被留给了用户。

### 2. 新用户的障碍不是不会点击，而是不知道如何开始

新用户经常同时面临三个问题：不知道该提供什么输入、不理解不同生成方式的差异，也不知道什么结果才适合自己的用途。社区中的优秀作品可以带来期待，却不能自动变成一条可执行路径。

### 3. 老用户每次回来仍像重新开始

对于已经有项目和资产的用户，首页更重要的价值不是再次教育“如何生成”，而是快速回答：哪里需要我处理、上次做到哪里、接下来最值得做什么。如果历史工作被隐藏在资产库深处，用户每次回访都要重新寻找上下文。

### 4. 专业价值没有被翻译成用户可以理解的结果

骨骼、PBR、UV、组件拆分等能力对专业用户有价值，但直接堆叠术语会提高理解门槛；反过来，如果只展示漂亮模型，用户又难以判断它是否能继续编辑、制作动画或进入后续流程。

### 5. 生成成本和结果风险暴露得太晚

参考图不清晰、主体构图不合适或细节模式选择错误，都可能导致用户在消耗积分后才发现结果不符合预期。这类失败不仅浪费额度，也会削弱用户对生成质量的信任。

## 三、整体产品策略

本次重构遵循四条原则。

### 1. 从工具入口转向任务入口

用户首先选择“做一个资产”还是“完成一个项目”，再选择使用图片或智能助理。信息架构从产品能力出发，改为从用户目标出发。

### 2. 核心创建区稳定，个性化发生在上下文层

中心创建入口对所有用户保持稳定，保证学习成本可控；新老用户差异主要体现在“继续工作 / 推荐起点”区域。这样既能提供个性化，也不会让首页因用户不同而完全失去一致性。

### 3. 先给结果和行动，再逐步解释专业能力

默认状态展示模型类别、项目状态和下一步；只有在悬停、展开或进入详情后，才展示更细的能力说明。这种渐进式披露让普通用户不会被术语淹没，同时保留专业用户需要的信息深度。

### 4. 不把演示包装成已完成能力

社区卡片的骨骼、材质和组件效果明确标注为“结构示意”“对比预览”或“拆分示意”，不能暗示某个社区资产已经完成对应生产处理。只有用户自己的项目状态，才可以表达“已完成”或“建议下一步”。

## 四、页面结构与逐项设计考量

### 1. 顶部导航：保留熟悉感，把创新放在工作区

当前设计保留 Meshy、社区、API、资源、创意工坊，以及 Agent、工作区、积分、升级、帮助、通知和账户入口。导航采用 56px 高度与紧凑的桌面操作尺寸。

**为什么保留：** 顶部导航承载的是产品身份、全局去向和账户状态，不是本轮需要重新发明的对象。保留原有信息架构，可以让现有用户确认自己仍处在 Meshy 中，把注意力集中在真正变化的创作流程上。

**相比原 Meshy：** 全局能力没有被重排，但重构后的深色粘性导航在长页面滚动时持续可见，使工作区、社区和账户入口始终可达。

### 2. 个性化问候：把首页从公共入口变成个人工作台

首屏使用“嗨，rosyy6778！你要在 3D 中创建什么？”作为任务提问，而不是营销标题或能力介绍。

**为什么加入：** 登录后用户已经完成了对产品的初步认知，此时最应该被回答的是“今天要做什么”。问候和行动问题共同建立个人工作台语境，也让下方的模式选择成为自然回答。

**相比原 Meshy：** 延续其登录后问候方式，但将问候更明确地连接到任务选择、项目规划和后续工作。

### 3. “单个资产 / 创建项目”：先区分任务规模

首屏第一层选择不是生成技术，而是任务类型：制作一个独立模型，或创建包含多个关联资产和阶段的项目。

**为什么加入：** 单资产与多资产项目在目标、上下文、依赖关系和确认节奏上完全不同。若用同一条生成流程承接两者，复杂项目会退化成多次互不关联的生成。

**单个资产适合：** 明确、独立、一次可描述清楚的模型需求。

**创建项目适合：** 多个相关资产、需要统一风格、存在先后依赖，或用户只有一个模糊概念的任务。

**相比原 Meshy：** 从“一次生成一个结果”扩展到“先规划，再拆分并跟踪多个任务”。当前页面用项目计划预览、七阶段示例和项目进度卡表达这一产品方向。

### 4. “图生 3D / 智能助理”：同时服务确定需求与模糊需求

单个资产模式提供“图生 3D”和“智能助理”；项目模式对应“参考图开始”和“智能规划”。

**为什么加入：** 有的用户已经有清晰参考图，希望快速得到结果；有的用户只有目标和约束，需要先澄清用途、风格与交付要求。两类用户不应该被迫走同一种输入流程。

**相比原 Meshy：** 保留图生 3D 这种低门槛入口，同时让 Agent 不只是另一个生成按钮，而是承担需求澄清和任务规划。

### 5. 图片添加与可用性检查：把失败预防放在扣费之前

页面允许添加单张或多张参考图片，并检查分辨率、清晰度和画幅，给出“图片可用”“建议调整后使用”或“建议更换图片”的反馈。高风险图片需要用户确认后才能继续。

**为什么加入：** 用户往往无法判断什么图片适合 3D 生成。提前反馈能够减少无效尝试，也让失败原因从“AI 不行”变成可理解、可修正的输入问题。

**相比原 Meshy：** 上传不再只是一个文件入口，而成为生成前的质量门槛和信任机制。多视图被解释为可选的理解辅助，而不是强制要求，也不声称未经验证的固定数量限制。

### 6. 智能规划提示：让用户不用先学会写专业 Prompt

智能助理输入框直接给出用途、风格、拓扑、材质和绑定等描述示例；项目模式则提示系统会追问并拆分工作。

**为什么加入：** 空白输入框会把表达负担交给用户。示例不是教程，而是通过占位内容展示“可以描述到什么程度”，帮助用户形成有效输入。

**相比原 Meshy：** 从“用户给一句话，系统给一个模型”扩展为“系统帮助补全目标、约束和交付要求”。

### 7. Skill 架构：从风格快捷方式扩展到生产任务

单资产 Agent 中的 Skill 被分成两组：

- **创意模板：** Chibi 手办、砖块人物、冰箱磁贴、扭蛋玩具、Low Poly、写实模型、动漫角色、玩具风格。
- **生产工具：** 游戏资产基础检查、3D 打印基础检查、PBR 材质补全、骨骼绑定、组件拆分。

**为什么这样分组：** 创意模板解决“我想生成什么样”，生产工具解决“这个模型生成后还能怎么推进”。两者都重要，但用户意图不同，混在一个列表里会让 Skill 退化成没有层级的功能集合。

**为什么删除“图片转 3D”Skill：** 图片转 3D 是基础输入方式，不是一项独立的生产任务。重复出现会混淆“输入方式”和“任务能力”的层级。

**相比原 Meshy：** 在保留风格模板降低首次尝试门槛的基础上，增加生成后的工作流价值，帮助产品从 creation moment 延伸到生产过程。

**能力边界：** 当前“游戏资产基础检查”和“3D 打印基础检查”只表达基础分析，不承诺自动 LOD、Unity/Unreal 完全兼容、材料重量估算、CAD 或制造可行性验证。

### 8. 项目模板：用目标场景代替工具清单

项目模式将“技能”改名为“项目模板”，提供制作可动画角色、验证产品外观方案、制作一套游戏道具、拆解场景并制作资产等入口。

**为什么加入：** 项目不是一个可以立即执行完的 Skill，而是一组需要计划、依赖和确认的任务。用目标场景命名，比让用户逐个挑选工具更接近真实工作方式。

**为什么选择后不立即生成：** 模板只用于填充和完善规划提示，必须先让用户确认计划，才能创建任务或消耗积分。这避免一次点击触发大规模、不可控的生成。

**相比原 Meshy：** 用户可以从模糊目标启动多资产工作，不必先理解每个底层工具，也不必靠多次独立生成手动维护一致性。

### 9. 紧凑命令行：让高频辅助项靠近输入，但不抢主操作

“添加图片”“技能 / 项目模板”和两个情境建议被放在同一行，展开内容仍留在创建卡片内部。

**为什么这样设计：** 这些都是输入阶段的辅助动作，应在需要时就近获得；同时它们不能比文本输入和主按钮更突出。卡片内流式展开也能保持空间关系，避免浮层遮挡细节模式或生成按钮。

**相比原 Meshy：** 输入辅助能力更集中，用户不用在页面不同区域寻找样例、附件和工具。

### 10. 标准 / 高细节模式比较：把技术参数翻译成选择后果

模式选择不仅显示名称，还比较速度、适用场景、几何表现、贴图表现和积分消耗趋势。

**为什么加入：** “标准”和“高细节”对不熟悉 3D 的用户并不构成有效决策。用户真正需要知道的是：是在快速试方向，还是为近景和正式交付投入更多时间与额度。

**相比原 Meshy：** 从参数选择升级为决策支持，降低用户一开始就使用高成本模式、或正式交付仍使用低细节模式的概率。

### 11. 生成前确认与积分提示：建立可控感

项目规划明确提示“确认前不会开始生成，也不会消耗积分”，每个项目任务也会在实际生成前分别确认细节等级与积分。

**为什么加入：** Agent 和项目模式越智能，用户越需要知道系统什么时候只是在规划、什么时候会真正执行和扣费。明确的阶段边界能够减少误操作焦虑。

**相比原 Meshy：** 把成本透明度从账户余额扩展到具体动作，让用户对复杂任务的执行节奏更有控制权。

### 12. “继续工作”工作板：让老用户从上下文返回

老用户视图首先展示进行中的项目，再按“待处理、继续工作、建议优化”组织资产；完成项目默认收起。

**为什么加入：** 老用户回来时最重要的问题不是“再生成什么”，而是“现在最需要我做什么”。按行动优先级组织，比按创建时间或文件类型排列更接近工作流。

**三个分组分别解决：**

- **待处理：** 需要用户做决定，避免项目停滞。
- **继续工作：** 直接恢复上次上下文，减少寻找成本。
- **建议优化：** 在已有结果上给出接近交付的下一步。

**相比原 Meshy：** 首页从重复启动生成，扩展为承接回访、续作和资产优化，直接服务留存。

### 13. 项目折叠卡：同时看全局进度与局部任务

进行中的项目卡展示总体进度、下一步、部分资产缩略图；展开后显示各资产的“已完成、下一步、等待中”状态。

**为什么加入：** 多资产项目既需要全局进度，也需要知道具体阻塞在哪里。折叠结构让用户先扫描项目，再按需查看细节，避免首页变成项目管理后台。

**相比原 Meshy：** 多次生成结果被组织成有关系的项目单元，用户能理解资产之间的依赖和推进状态。

### 14. 新用户“推荐起点”：没有历史数据时也提供可执行路径

页面通过演示视图展示新用户状态：没有历史项目时，将“继续工作”替换为基于使用偏好的快速开始、推荐工作流与建议优化示例。

**为什么加入：** 个性化不能只对有历史数据的用户有效。新用户需要的是少量、可解释、可立即启动的建议，而不是一个完全空白的项目区域。

**相比原 Meshy：** onboarding 中收集的游戏开发、3D 打印、产品设计等意图可以继续影响首页内容，不再只用于一次性注册分流。

**当前实现说明：** “老用户 / 新用户”开关是用于展示两种产品状态的原型控制，不是计划保留给正式用户的 Meshy 导航。

### 15. 社区 Gallery 下沉：从首页主角变成工作之后的灵感层

社区内容位于创建与继续工作之后，保留真实模型素材、类别、作者和互动信息。

**为什么下沉：** 登录后首页的第一任务应该是开始或继续工作。社区内容仍然负责激发灵感、建立质量预期和提供参考，但不应抢占核心创作入口。

**相比原 Meshy：** Gallery 从“证明平台能生成漂亮内容”转为“为当前创作寻找参考和起点”。详情中的“以此为灵感开始创作”也将浏览重新连接到行动。

### 16. 搜索、频道、分类和排序：让灵感可以被主动寻找

Gallery 支持按模型、作者或标签搜索，并提供全部 / 3D 打印频道、资产类别、演示预览和推荐 / 热门 / 最新排序。

**为什么加入：** 灵感浏览只有在内容少时可以完全依赖滚动；当内容增长后，用户需要按自己的用途主动缩小范围。搜索和筛选把社区从被动内容流转为可检索的参考库。

**相比原 Meshy：** 保留社区发现感，同时加强用途导向和结果可控性，减少无限浏览造成的行动中断。

### 17. 能力 Hover 演示：在不增加阅读负担的情况下解释 3D 价值

社区模型悬停时展示骨骼结构、材质对比或组件拆分的视觉演示；键盘聚焦触发同样状态。

**为什么加入：** 3D 能力用静态术语很难理解，用轻量视觉变化可以让用户快速感知“可动画”“材质可调整”或“部件可编辑”的含义，同时不需要为每张卡增加大段文字。

**为什么必须写成“示意 / 预览”：** 动画效果只是能力教育，不代表该社区模型已完成绑定、PBR 或拆件。默认卡片只展示角色、动物、家具等真实资产类别，避免形成虚假能力承诺。

**相比原 Meshy：** 社区作品除了展示结果，还承担能力教育；但当前方案主动校正了“演示效果等于资产状态”的误导风险。

### 18. 大图详情与创作 CTA：让浏览形成行动闭环

点击社区卡片后打开大图预览，保留资产类别、作者和能力演示说明，并提供“以此为灵感开始创作”。

**为什么加入：** 用户从缩略图产生兴趣后，需要先确认完整轮廓和细节，再决定是否采用。明确 CTA 则把“看到了喜欢的作品”转化为“开始一项创作”。

**相比原 Meshy：** 社区浏览不再是独立终点，而是回到创建工作流的一个入口。

### 19. 升级入口：在生产价值出现后再表达商业价值

页面右下角保留“生产级工作流”的升级入口，关联额度、专业导出与私有资产。

**为什么这样放：** 付费提示不应打断核心创建，但应在用户已经看到项目管理、生产工具和后续流程价值时保持可见。升级理由也从抽象会员权益转向与工作直接相关的能力。

**相比原 Meshy：** 转化叙事不只依赖更多生成次数，而是强调专业工作流和资产管理带来的持续价值。

## 五、与原 Meshy 相比，重构后能做什么

| 用户任务 | 原体验的主要方式 | 重构后的能力 | 产品价值 |
| --- | --- | --- | --- |
| 开始一个模型 | 选择生成入口并自行组织输入 | 先选择单资产，再用图片或智能助理开始 | 降低首次启动门槛 |
| 从模糊想法开始 | 用户自行写 Prompt 和拆解需求 | Agent 通过示例、模板和规划提示补全目标 | 提高有效输入率 |
| 制作多个关联资产 | 多次独立生成并手动管理 | 创建项目、预览计划、拆分任务、跟踪资产状态 | 支持更长、更复杂的工作 |
| 判断图片是否合适 | 生成后再从结果判断 | 生成前检查分辨率、清晰度和画幅风险 | 降低无效积分消耗 |
| 选择质量模式 | 理解参数后自行决定 | 对比速度、用途、几何、贴图和成本 | 减少模式误选 |
| 生成后继续处理 | 再寻找独立工具或重新开始 | Skill 提供基础检查、材质、绑定和拆件入口 | 延长使用链路 |
| 回到历史工作 | 从资产列表寻找上次内容 | 首页展示项目进度、阻塞点和下一步 | 提升续作率与留存 |
| 新用户寻找方向 | 浏览社区并自行模仿 | 根据使用偏好给出可解释的推荐起点 | 提升首次成功率 |
| 浏览社区作品 | 主要看结果和热度 | 可搜索、筛选、查看能力演示并开始同类创作 | 将灵感转化为行动 |
| 理解专业能力 | 阅读术语或进入具体工具 | 用渐进式视觉演示解释能力及用途 | 提高专业价值感知 |

## 六、对核心产品指标的预期影响

### Activation：让用户更快完成第一次有效行动

关键机制包括任务类型选择、Prompt 示例、项目模板、图片可用性检查和模式比较。建议关注：

- 首次创建入口点击率。
- 首次有效输入完成率。
- 注册到首次生成的耗时。
- 图片风险提示后的修正率。
- 推荐起点到创建的转化率。

### Retention：让用户回来后可以直接接着做

关键机制包括继续工作、项目进度、下一步建议和完成项目收纳。建议关注：

- 首页到历史项目的续作率。
- 建议下一步的点击与完成率。
- 项目创建后的次日、七日回访率。
- 多资产项目的任务完成深度。

### Conversion：让付费理由从“生成更多”扩展为“完成工作”

关键机制包括高细节模式、生产工具、项目管理、专业导出与私有资产表达。建议关注：

- 高细节模式选择后的付费转化。
- 生产工具使用用户的付费率。
- 项目用户与单次生成用户的付费差异。
- 升级入口在不同工作阶段的点击率。

## 七、关键假设与验证方式

### 假设 1：用户更容易理解任务，而不是工具名称

验证“单个资产 / 创建项目”是否比直接罗列生成工具带来更高的启动率，并观察用户是否能正确选择模式。

### 假设 2：生成前反馈可以提高信任，而不是增加阻力

对比有无图片检查时的生成完成率、图片替换率、失败重试率和用户对结果的满意度。

### 假设 3：老用户更需要下一步，而不是更多灵感

对比“继续工作”与传统社区 Feed 在老用户首页的点击率、续作率和回访后首个动作耗时。

### 假设 4：能力演示可以提升专业价值感知

测试普通静态卡片与带有明确“示意 / 预览”标识的交互卡片，关注详情打开率、相关 Skill 使用率和升级意愿，同时检查是否产生能力误解。

### 假设 5：项目模式能够承接更高价值的长期任务

观察项目创建率、规划确认率、任务完成深度、跨日回访和项目用户付费率，判断用户是否真的需要首页级项目编排。

## 八、当前原型边界

这是一套桌面端产品交互原型，目标视口为 1440px，不包含移动端和平板适配。当前页面用于验证信息架构、交互顺序与价值表达，不代表以下能力已经接入真实生产系统：

- 登录、上传、生成、计费和项目数据仍为前端演示状态。
- 图片检查是轻量本地规则，不等同于完整的 3D 输入质量模型。
- 项目规划、七阶段任务与进度为交互原型，不会真正调度生成任务。
- 游戏资产和 3D 打印只展示基础检查方向，不构成引擎兼容或制造可行性保证。
- 社区卡片的骨骼、材质和组件效果是能力演示，不是对应资产的真实处理记录。
- 老用户 / 新用户切换仅用于方案展示，正式产品应由账户状态和行为数据自动决定内容。

这些边界并非方案缺口，而是产品可信度的一部分：原型要验证的是用户是否理解并需要这套工作方式，而不是用静态页面假装后端能力已经完成。

## 九、后续落地优先级

### P0：验证首页任务架构

- 接入真实的最近项目和资产状态。
- 让“继续工作”能够进入对应任务。
- 埋点验证单资产、项目和新用户推荐起点的使用差异。

### P1：建立可靠的生成前决策支持

- 用真实服务替换轻量图片检查。
- 接入模式价格、预计耗时和积分确认。
- 保存 Agent 对话和项目规划上下文。

### P2：验证生成后的工作流价值

- 先接入一到两个可真实完成的生产工具，例如基础资产检查或骨骼绑定。
- 用真实状态驱动“建议优化”，并说明建议原因。
- 验证生产工具是否提升留存、项目深度和付费率。

### P3：把社区参考连接到创建

- 将“以此为灵感开始创作”接入可控的 Remix 或参考图流程。
- 根据当前项目和 onboarding 目标排序社区内容。
- 保留探索性，避免推荐把用户限制在单一场景中。

## 十、结论

这次重构最重要的产品判断，是首页不应只承担“开始一次生成”和“展示优秀作品”两件事。随着 AI 让模型生成越来越容易，真正影响用户长期价值的问题会逐渐变成：如何描述目标、如何控制成本、生成后做什么、怎样把多个资产组织成一个可以完成的项目。

因此，重构后的首页同时承担三种职责：

1. **创作入口：** 让明确需求和模糊需求都能低成本开始。
2. **工作续接：** 让老用户回到项目上下文，并获得清晰下一步。
3. **能力发现：** 让社区内容不仅展示结果，也帮助用户理解 Meshy 能如何进入真实工作流。

最终目标不是让首页看起来更复杂，而是让用户在任何阶段进入 Meshy 时，都能更快回答三个问题：

> 我现在要做什么？我下一步该做什么？Meshy 为什么值得继续使用？
